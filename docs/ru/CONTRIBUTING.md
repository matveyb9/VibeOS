# Участие в VibeOS

**Статус:** Утверждённое направление проекта

VibeOS использует короткие тематические ветки и Pull Request. Ветка `main` должна оставаться собираемой и загружаемой в поддерживаемом профиле QEMU, когда toolchain появится.

## Ветки

Используйте строчные английские имена с понятным префиксом: `feature/`, `fix/`, `docs/`, `spec/`, `test/`, `refactor/`, `security/` или `release/`. Одна ветка решает одну связанную задачу.

## Коммиты

Используйте английский заголовок в формате:

```text
type(scope): short imperative description
```

В теле каждого коммита должны быть оба языковых блока:

```text
**🇺🇸 [EN]**: Detailed English description.

**🇷🇺 [РУ]**: Подробное описание на русском языке.
```

Используются типы `feat`, `fix`, `docs`, `spec`, `test`, `refactor`, `build`, `ci`, `security` или `chore`. Несовместимое изменение контракта добавляет английский footer `BREAKING CHANGE:` после обоих языковых блоков.

## Pull Request

Заголовки Pull Request используют тот же английский формат. Английское описание обязательно. Русское резюме рекомендуется и обязательно, если изменение влияет на безопасность, ABI, VaultFS, загрузку или другой утверждённый архитектурный контракт.

Каждый Pull Request объясняет цель, изменение поведения, проверку, влияние на документацию, совместимость и безопасность. Изменение не считается завершённым, пока утверждённая документация описывает устаревшее поведение.

## Релизы

Release notes содержат сначала английский, затем русский раздел. Оба заголовка выделяются жирным: **🇺🇸 ENGLISH** и **🇷🇺 РУССКИЙ**. Публичные релизы будут включать подписанные образы, контрольные суммы, статус поддержки, известные ограничения и инструкции обновления или отката.
