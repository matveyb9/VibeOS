# Обзор архитектуры

**Статус:** Утверждённое направление проекта

VibeOS — нативная настольная ОС. Её архитектура строится как набор независимых подсистем, связанных явными контрактами, а не приватными зависимостями между частями проекта.

## Путь системы

```text
Prelude → Dawn Context → Pulse → Atlas / Vault / Relay → Prism → Horizon → Parcel → приложение
```

`Prelude` — независимая загрузочная среда. Она поддерживает запланированные пути UEFI и legacy BIOS, проверяет выбранный системный образ и передаёт ядру Dawn Context.

`Pulse` — модульное монолитное ядро. Оно управляет памятью, задачами, прерываниями, планированием, системными вызовами и Pulse Objects. Приложения и службы используют непрозрачные Keys вместо прямого доступа к данным ядра.

`Atlas` отвечает за обнаружение оборудования, шины, драйверы и ограниченные Device Grant. `Vault` отвечает за VFS, VaultFS, тома, журналирование и A/B-разметку системы. `Relay` предоставляет типизированные Links, сообщения, события и контролируемую передачу Keys.

`Prism` — пользовательский композитор. `Canvas` — UI SDK на C17. `Horizon` управляет сессией рабочего стола, политикой окон, уведомлениями, первым запуском и Safe Session. `Parcel` проверяет и устанавливает VPK-пакеты.

## Модель приложений

Приложения используют Origin, Facet, Canvas, Vault Kit и Meridian Kit. Они получают минимальный набор Keys, необходимый для работы. Файл выбирается через Harbor и передаётся ограниченным Vault Entry Key; приложение не получает автоматически доступ ко всему профилю пользователя или системному хранилищу.

## Режимы запуска

VibeOS проектируется для трёх режимов: stateless Live, Live + Vault с постоянным хранилищем и полной A/B-установки. Recovery, Safe Session, Prelude Console и Pulse Console предоставляют многоуровневую диагностику и восстановление, не превращая консоль ядра в неограниченный административный shell.
